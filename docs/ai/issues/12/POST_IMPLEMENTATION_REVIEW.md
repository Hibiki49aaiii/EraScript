## Correctness — PASS

The runtime no longer changes the application's module location.

Node performs normal resolution from the original `.era` URL, while the custom loader only handles file URLs ending in `.era`.

Relative EraScript modules, relative JavaScript modules, and bare npm imports are independently regression-tested.

## Diagnostics/source maps — PASS

Imported EraScript diagnostics are remapped with a per-module coordinate map.

Runtime stack frames from imported EraScript modules resolve to the original imported `.era` path and source line.

No duplicate source-map implementation was introduced.

## Architecture — PASS

The implementation delegates non-Era loading to Node rather than emulating/copying a project tree.

The TypeScript checker uses virtual files only internally and keeps runtime URLs untouched.

Runtime cycles remain Node-owned; checker cycles remain TypeScript-program-owned.

## Security — PASS

The custom loader:

- only intercepts `file:` URLs whose filesystem path ends in `.era`,
- does not add module search paths,
- does not rewrite npm package specifiers,
- does not persist generated JavaScript/maps,
- does not copy project files/secrets into staging,
- adds no npm dependency.

## Compatibility — PASS WITH EXPLICIT MINIMUM

`node:module.register()` exists from Node 20.6.0, so package metadata now declares `node >=20.6.0` instead of the overly broad `>=20`.

The lockfile was regenerated by npm rather than manually edited.

## Maintainability — PASS

Project config parsing is isolated in `src/project.ts`.

Runtime transformation is isolated in `src/runtime-loader.ts`.

Existing `compile()`, frontend transforms, coordinate mapping, and diagnostics are reused.

## Remaining limitation

Standalone multi-file `era build` emission remains intentionally out of scope. The runtime/check graph contract is now stable enough for that to become a separate next issue.
