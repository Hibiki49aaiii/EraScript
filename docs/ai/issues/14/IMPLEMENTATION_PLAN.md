## 1. Isolated Waku dependency root

Create:

```text
test/live/waku-deps/package.json
test/live/waku-deps/package-lock.json
```

Manifest:

```json
{
  "private": true,
  "dependencies": {
    "@railgun-community/waku-broadcaster-client-node": "9.1.1"
  }
}
```

The lockfile must be generated by npm 10 on Node 22. It must not be manually synthesized.

## 2. Live test resolution

Modify `test/live/railgun-waku.live.ts` so the package specifier is resolved as follows:

- when `RAILGUN_WAKU_DEPS_ROOT` is defined, create a Node resolver rooted at that directory's `package.json`,
- resolve the Waku package entry from the isolated `node_modules`,
- dynamically import the resulting file URL,
- otherwise keep the existing bare-package fallback for developer environments.

This preserves the live test's behavior while making CI deterministic.

## 3. Live workflow

Change both jobs to root `npm ci`.

RAILGUN/Waku job additionally runs:

```bash
npm ci --prefix test/live/waku-deps
```

and sets:

```text
RAILGUN_WAKU_DEPS_ROOT=<workspace>/test/live/waku-deps
```

No `npm install --no-save` remains.

## 4. Dependency audit workflow

Add `.github/workflows/dependency-audit.yml`.

Triggers:

- manual dispatch,
- scheduled weekly check,
- push/PR changes to root or isolated dependency manifests/lockfiles or the audit workflow.

Jobs/checks:

### Production gate

```bash
npm audit --omit=dev --audit-level=high
```

This is blocking.

### Root dev/test evidence

```bash
npm audit --json
```

This is captured without failing due to Issue #11's known upstream RAILGUN dev/test findings.

### Isolated Waku evidence

```bash
npm audit --prefix test/live/waku-deps --json
```

Also evidence-only until its actual baseline is measured and reviewed.

The workflow must print deterministic summary counts so drift is visible in logs.
